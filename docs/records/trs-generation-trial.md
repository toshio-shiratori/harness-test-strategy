## 3. 判定の基準

迷った判定は、厳しい側に倒した。ただし、目次の効果は、厳しい側がどちらか決まらない。

### 3.1 OI の発見

| 判定 | 規則 |
|---|---|
| 発見 | 主な問いが、候補の論点として独立に立てられている |
| 一部 | 問いが複数あって一部だけ出ている。または、別の候補の説明文に一言あるだけである |
| なし | 主な問いが出ていない |

- 合否は「発見」だけで数え、「一部」を含めた値も併記する。
- 具体値の推奨が違っても、問いが同じなら発見とする。

### 3.2 期待結果の再現

| 判定 | 規則 |
|---|---|
| 一致 | 同じ条件の行があり、期待結果が同じである |
| 一部対応 | 条件の一部だけに、生成側の行がある |
| 食い違い | 同じ条件で期待結果が違う。根拠を両方引用する |
| 対応なし | 生成側に、その条件の行がない |
| 生成側が未決 | 生成側が、期待結果を決めずに未決に残した |

期待結果の要素が生成側に無いときは、一致にして備考に欠けを書く。

### 3.3 AC の網羅

層を問わずに見ると、層違いの重複が簡単に「含む」になる。そこで、次の規則で一部とした。

| 判定 | 規則 |
|---|---|
| 含む | 今の AC の主題の振る舞いが、生成側の AC にあり、下の R1〜R3 に当たらない |
| 一部 | 主題はあるが、R1〜R3 のどれかに当たる |
| なし | 主題の振る舞いが、生成側のどの AC にもない |

| 規則 | 一部とする場合 |
|---|---|
| R1 層 | 今の AC が、DB や HTTP を通した往復を確かめるのに、生成側に同じ層の AC がない |
| R2 の表明 | 今の AC が、登録されない、変わらないを表明するのに、生成側の対応する AC にその表明がない。または、その AC が専用に持つ拒否の類型が、生成側の例にない |
| R3 その他の欠け | 今の AC の Then の要素か、その AC が専用に持つ入力の類型が、生成側の対応する AC にない |

例の値が違っても、入力の類型が同じなら含むとした。類型は、今の TRS の水準の単位とする。

- AC-04-03 は一部にした。期待結果の区分「完了」が、生成側の層2の AC にない。
- AC-01-27 は一部にした。別形式(F2-L5)の例が、HTTP の AC にない。
- AC-01-41 は含むにした。5 例はすべて水準 F1-L17 で、C:AC-01-07 も同じ水準である。

## 10. 考察

### 10.1 結果の読み方

### 10.2 目次の効果

- 発見数ではなく、要件定義書の抜けを検査する効果として読むのが妥当である。

### 10.3 本番の適用に向けた所見

- 一部の 16 件の欠けは、制約の行の要素が 4 件、拒否の類型が 7 件、層が 2 件、Then の要素が 2 件、例の類型が 1 件である。生成の入力か検査で、これらを満たす規則が要る。

- 生成 C は、決められない点を 20 件の未決に残した。推測しない動きは、期待値を人が決める方針と合う。
- 候補の数は、A が 38 件、B が 49 件で、今の OI の 17 件を超える。対応しない候補の仕分けが、人の負担になる。
- 7.1 の漏れの候補 5 行は、今の TRS に AC を足すかの判断の材料になる。
