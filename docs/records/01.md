# 01 基本方針書に関わる、このリポジトリの運用の記録

このリポジトリが[01 基本方針書](../testing/01-test-policy.md)の品質ゲートをどう運用しているかの記録である。配布の対象ではない。導入先は、自分のプロジェクトの環境で決める。

## G0 文書検査

| 項目 | 内容 |
|---|---|
| CI | `.github/workflows/lint.yml` の `lint` ジョブ |
| コマンド | `npm ci && npm run lint`(ローカルも CI も同じ) |
| 対象 | 本リポジトリの全 `.md`。この範囲は本リポジトリ自身の規則であり、導入先では適合度診断で決める |
| 本リポジトリ固有の検査 | `npm run lint` は、G0 の条件の検査(`lint:md`・`lint:mermaid`)に加えて、`lint:refs`(`scripts/check-section-refs.mjs`。02a・02b・02c の節番号参照とリンクの検査)と `lint:portable`(`scripts/check-portable.mjs`。`docs/testing/` の言語中立・自己完結の検査。外へのリンク、言語のコードブロック、このリポジトリ固有の語を失敗にし、自己テストを持つ)も実行する。`lint:mermaid` の幅の検査(描画した図の幅が 900px を超えたら失敗)も本リポジトリ固有で、G0 の条件(構文の指摘、図がレンダリングできない)には含まれない。`lint:refs` と `lint:portable`、`lint:mermaid` の幅の検査は導入先に求める要件ではない |

## ブランチの保護と必須チェック

`main` は GitHub のルールセット(Protect main)で、PR 必須・force push と削除の禁止・必須チェックを強制する。登録済みの必須チェックは `lint` / `test` / `check` / `integration` / `e2e` である。

| 必須チェック | ワークフロー | 対応するゲート |
|---|---|---|
| `lint` | `lint.yml` | G0 |
| `test` | `kotlin-samples.yml` | G1・G2・G3・G5 |
| `integration` | `kotlin-samples.yml` | G4(Integration) |
| `e2e` | `kotlin-samples.yml` | G4(E2E) |
| `check` | `pr-bug-fix-check.yml` | ゲートではない。バグ修正 PR の還元先と完了条件の欄を検査する([04](../testing/04-regression-governance.md))。ワークフローとの対応は、ジョブ名が `check` のワークフローがこれだけであることによる |

## G3 導入期の例外

本リポジトリは導入期の例外([02b §4.1](../testing/02b-execution-and-mutation.md#41-適用タイミングと閾値))を使わない。上表のとおりに運用する。

## 人間のレビュー

一人運用のため承認数を要求せず、`.github/CODEOWNERS` で対象ファイルの責任者を明示するに留める。複数人になった時点で、ルールセットの `require_code_owner_review` を有効にする。
