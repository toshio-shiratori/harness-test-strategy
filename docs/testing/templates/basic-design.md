# 基本設計書: <機能名>

> 使い方: このファイルを `<機能ID>-<機能名>.md` としてコピーして使う。置き場所は導入先の基本設計書ディレクトリ（例: `docs/design/`）。
> 山括弧 `< >` と `例:` の行は置き換え／削除すること。この基本設計書は、[要件定義書](./requirements.md)を実現する方式を書き、TRS を起草するときの入力になる。書く範囲は [03 §5](../03-trs-guideline.md#5-策定フロー) に従う。
> **節 2 から 9 の項目には ID を付ける。書式は `DES-<略号>-<番号>` とし、略号は要件定義書の「要件 ID の略号」と同じにする。節 1 の全体構成には ID を付けない。**
> 用語は[要件定義書の用語](./requirements.md#22-用語)を使う。

## 10. 未決事項

> 基本設計を書く中で起きた、まだ決まっていない問いを書く。ID は項目 ID と区別するため `Q-<番号>` とする。行は消さない。担当の列には、決める人を書く。
> 項目 ID と要件 ID の形の文字列は、この表に書かない。
> 番号は文書ごとに 01 から振る。ほかの文書から指すときは、文書名を添える（例: 基本設計書 Q-01）。
> 決まったときの書き方と、決まらなかったときの扱いは、[要件定義書の未決事項](./requirements.md#8-未決事項)と同じにする。要件の表は、項目の表と読み替える。
