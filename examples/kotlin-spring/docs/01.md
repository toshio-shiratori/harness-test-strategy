# 01 基本方針書の実現例(Kotlin + Spring Boot)

**この文書で示すこと**

- [01 基本方針書](../../../docs/testing/01-test-policy.md)の品質ゲート G1〜G5 を、このサンプルがどう実現しているか
- 基本方針書の本文から移した、Kotlin + Spring Boot 固有の記述

これは導入の一例で、規範ではない。規範は基本方針書の本文であり、導入先はプロジェクトの言語・ビルドツールに合わせて実現方法を選ぶ。

## 1. ゲートの実現

| ゲート | このサンプルの実現 | CI |
|---|---|---|
| G1 静的検査 | コンパイル(`allWarningsAsErrors`)と `./gradlew detekt ktlintCheck`。アーキテクチャ検査(Konsist)は G2 の `test` で実行する | `kotlin-samples.yml` の `test` ジョブ |
| G2 層1テスト | `./gradlew test` | 同 `test` ジョブ |
| G3 ミューテーション | `./gradlew pitest`(PIT)。PR は差分(`ALL` のときは全体)、main への push と夜間は全体。いずれもドメイン層のクラスが対象に入るときは、ドメイン層だけの実行(`-Ppitest.domainOnly=true`)も併走する | `kotlin-samples.yml` の `test` ジョブ。夜間は `nightly-mutation.yml` |
| G4 層2テスト | `./gradlew integrationTest` と `./gradlew e2eTest` | 同 `integration` ジョブと `e2e` ジョブ |
| G5 TRS 整合 | `TraceabilityTest`(`./gradlew test` で実行) | 同 `test` ジョブ |

G4 は層1の `test` と別ジョブにしてある([02b §3.2](../../../docs/testing/02b-execution-and-mutation.md#32-層1統合テストe2e-の実行境界))。

## 2. G4 の構成

- Integration: `@WebMvcTest` + `RestTestClient`。Testcontainers の MySQL を使う DB 統合も含む。`integration` ジョブで PR に対して実行する。
- E2E: Playwright の Chromium(`src/e2eTest`)。`e2e` ジョブで PR に対して実行する。

## 3. G5 の検査

`TraceabilityTest` が、G5 の条件を検査する。検査する項目は、テストの有無、`@pending` の要否、`@pending` に書ける ID、関連列の AC である。条件の定義は[基本方針書 §5.1](../../../docs/testing/01-test-policy.md#51-ゲートと必須チェックの対応)と[03 §3.4](../../../docs/testing/03-trs-guideline.md#34-トレーサビリティ)を正とする。
