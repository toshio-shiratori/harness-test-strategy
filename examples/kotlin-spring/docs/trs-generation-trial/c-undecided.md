# 入力から決められなかった点

推測で埋めず、ここに残した。U は期待値が決められない点、D は入力の不足・食い違いと、読み取りの確認である。

## 期待値が未決の点(U)

制約の列に行があるものは、[c-constraints.md](./c-constraints.md) で「未決」と書いた行である。「—」は制約の行を作っていない。

| ID | 論点 | 制約 | 入力に書いてあること | 決める人に聞くこと |
|---|---|---|---|---|
| U-01 | タイトルが `null` のときの応答 | C-44 | OI-001 は欠落を `TITLE_BLANK` とする。OI-013 は数値・真偽値・配列・オブジェクトを `MALFORMED_REQUEST` とする。`null` はどちらにも無い。期限の `null` は期限なし(OI-012)だが、タイトルには無い | `TITLE_BLANK` か `MALFORMED_REQUEST` か |
| U-02 | 型違いと、別の項目の理由が同時にあるときの `codes` | C-111 | OI-011 は「理由はすべて集める」、OI-013 は型違いを `MALFORMED_REQUEST` とする。両方に当たるときの中身が無い。例: タイトルが数値で期限が `2026-13-01` | `MALFORMED_REQUEST` だけか、他の理由も入れるか |
| U-03 | 途中の表示されない文字と、残した組になる文字を、字数でどう数えるか | C-23, C-24 | OI-008 は UAX #29 に従うとするが、AC の例は結合文字と国旗に限る。見た目 50 字に途中の `[U+200B]` を足した例、残した `[U+FE0F]` を含む 50 字の例は、この限定の外にある | UAX #29 のとおりに数えた結果を AC の例にしてよいか。見た目の字数と違うとき、それでよいか |

## 入力の不足・食い違い(D)

## 読み取りの確認

いずれも期待値を入れたが、解釈を含むので確かめたい。

| ID | 読み取り | 根拠 | 影響する行 |
|---|---|---|---|
| R-01 | 区分の「未完了」と、完了の状態の「完了していない」を分けた。期限切れのタスクも完了していないので、完了にでき、未完了のグループに並ぶ | REQ-TODO-04 と REQ-TODO-32 は語が重なる。REQ-TODO-23、OI-003 から読んだ | C-164, C-166, C-186 |
| R-02 | `U+2800` や制御文字など、White_Space でも Default_Ignorable_Code_Point でもない文字は、見えなくても「表示される文字」である | OI-017 の定義の文字どおりの読み | 行は作っていない |
| R-03 | 未知の選択を拒否したとき、保存済みの選択は変わらない | OI-013 は 400 だけを定める。拒否と REQ-TODO-11 から読んだ | C-203 |
| R-04 | 期限の前後の空白は除かず、別形式として拒否する | 除去の決定はタイトルだけである(OI-017)。OI-005 の「それ以外」から読んだ | C-90 |
