# Open Issue の候補: タスク管理（登録・完了・一覧と期限）

要件定義書から期待値を決められない点の一覧である。AI の推奨は判断の材料で、決定ではない。決定は人間が行う。

- 区分の基準: AC の期待値（Then）を書くのに決定が要るものを `Blocking`、AC の期待値を書けて、画面の細部や一部の水準だけに関わるものを `Non-blocking` とした。
- 水準に関わる ID は `factors.md` の備考から参照している。画面の文言や挙動だけに関わる ID（OI-001、005、006、011、026、030〜034、036、037）は、水準にしていないので参照が無い。
- AC は未起草なので、関連は要件 ID で書く。TRS へ起票するときは、Blocking の関連列に AC を書き、その AC に `@pending:<OI-ID>` を付ける。
- 要件定義書の未決事項 Q-19、Q-20、Q-21 は、OI-001、OI-002、OI-003 に当たる。

## 候補にしなかった点

要件から答えが導けるか、期待値に関わらないので、起票しない案である。

| 点 | 扱い |
|---|---|
| 過去の期限で登録したタスクの区分 | REQ-TODO-20、21 から、登録の直後から期限切れと導ける |
| 期限の当日が期限切れでないこと | REQ-TODO-21 から導ける |
| 戻したタスクの一覧の位置 | REQ-TODO-27 は登録の順なので、完了の前と同じ位置に戻ると導ける |
| 初めて開いたときと、一度も切り替えていないとき | どちらも前回の選択がないので、REQ-TODO-30 で同じ結果になる |
| タスクの編集と削除、期限の変更 | 要件定義書 §1 の範囲の外である |
| 1 つの行に複数のことが書かれた要件（REQ-TODO-22、26、27） | 要件定義書のチェックリストの「1 つの要件に 1 つのこと」に沿わないが、期待値は決まる。要件定義書の修正を人間が判断する |
