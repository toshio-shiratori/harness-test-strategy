# 02a 型設計とPBT: Kotlin + Spring Boot のコード例

標準の [02a 型設計とPBT](../../../docs/testing/02a-types-and-pbt.md) は、言語・ライブラリに依存しない規範である。この文書は、その規範を Kotlin + Spring Boot 4.1.x で実装したコード例と、このサンプルで実測して分かった点を、規範と同じ節番号で並べたものである。

コード例は `examples/kotlin-spring/src/` に同一内容で置いてあり、`examples/kotlin-spring/` で `./gradlew test` を実行するとコンパイルとテストが走る（CI: `.github/workflows/kotlin-samples.yml`）。**コード例を変更するときは `src/` 側も同時に更新すること。**

コード例は **Kotlin + Spring Boot 4.1.x** で示す。原則そのものは言語非依存である。

## 1. 「誤りを書けなくする」型設計

### 1.1 プリミティブ型の排除（ドメイン型 / Value Object 化）

Kotlin では `@JvmInline value class` を使うと、実行時のオブジェクト生成コストを抑えつつ、コンパイル時に型を区別できる。

```kotlin
package com.example.todo.domain

/** タスクの識別子。登録ごとに増える番号で、登録時刻が同じタスクの新旧を決める。別の識別子・番号との取り違えをコンパイルエラーにする。 */
@JvmInline
value class TaskId(val value: Long)
```

`TaskId` と `TaskTitle`（§1.2）は別の型なので、`Task.register` の引数の取り違えはコンパイルエラーになる。

```kotlin
package com.example.todo.domain

import java.time.Clock
import java.time.Instant

/** タスク。登録時刻は一覧の並び順（登録の古い順）に使う。 */
data class Task(
    val id: TaskId,
    val title: TaskTitle,
    val dueDate: DueDate?,
    val status: TaskStatus,
    val createdAt: Instant,
) {
    companion object {
        /** 未完了のタスクを登録する。期限が過去の日付でも登録できる。登録時刻は注入された Clock の現在時刻。 */
        fun register(id: TaskId, title: TaskTitle, dueDate: DueDate?, clock: Clock): Task =
            Task(id, title, dueDate, TaskStatus.Open, clock.instant())
    }
}
```

```kotlin
Task.register(TaskId(1), title, dueDate, clock)
// Task.register(title, TaskId(1), dueDate, clock)  // ← コンパイルエラー（TaskId と TaskTitle の取り違えを排除）
```

サンプルの判断: `TaskId` は、リポジトリが払い出す番号（登録ごとに増える番号）を包むだけで、拒否する値が無いので、コンストラクタを公開している。番号の払い出しは、ドメインのポート `TaskRepository.nextId()` に置く。実装は採番専用の表の `AUTO_INCREMENT` を使う（[02b §3.3](./02b.md#33-db-を含む-integration-のサンプルtestcontainers)）。

規範の規則との対応は次のとおり（規範は [02a §1.1](../../../docs/testing/02a-types-and-pbt.md#11-プリミティブ型の排除ドメイン型--value-object-化)）。

- 規則3: 生成は §1.2 のとおり `private constructor` + ファクトリ経由に限る。`as` による強制キャストで型を偽装してはならない。
- 規則4: `!!`（非 null アサーション）、根拠のない `as`、`@Suppress`、`lateinit` の乱用は静的解析（detekt）で禁止する。
- 規則5: `@RequestBody` 等で受ける DTO はプリミティブでよい。**DTO はアダプタ層に閉じ込め**、ユースケースへ渡す前にドメイン型へ変換する。このサンプルの DTO は `RegisterTaskRequest` で、例は §1.2 にある。

### 1.2 コンストラクタ防御

```kotlin
package com.example.todo.domain

/** 検証結果。失敗を例外ではなく値として返し、呼び出し側に分岐を強制する。 */
sealed interface Validated<out T, out E> {
    data class Valid<out T>(val value: T) : Validated<T, Nothing>
    data class Invalid<out E>(val error: E) : Validated<Nothing, E>
}
```

```kotlin
package com.example.todo.domain

import java.text.BreakIterator

enum class TitleError { BLANK, TOO_LONG }

/**
 * タスクのタイトル。両端の空白と表示されない文字を除いた後の、書記素（見た目の 1 文字）で 1〜50 字。
 * 空白は Unicode の White_Space 属性を持つ文字で、表示されない文字は Default_Ignorable_Code_Point 属性を持つ文字（U+200B など）。
 * 先頭からは、最初の表示される文字（空白でも表示されない文字でもない文字）より前を、すべて除く。
 * 末尾からは、最後の表示される文字より後ろを除く。ただし、その文字の直後に続く、異体字セレクタとタグ文字（OI-017 の範囲）は残す。
 * 直前の文字と組になって意味を持つので、組になる相手が無い位置のものは除く。
 * 途中の空白と表示されない文字は除かず、そのまま保存する。Unicode 正規化はしない。
 * 空白と表示されない文字だけでできたタイトルは、異体字セレクタとタグ文字だけでも、BLANK で拒否する。
 */
@JvmInline
value class TaskTitle private constructor(val value: String) {
    companion object {
        const val MAX_LENGTH = 50

        fun of(raw: String): Validated<TaskTitle, TitleError> {
            val trimmed = raw.trimEdges()
            return if (trimmed.isEmpty()) {
                Validated.Invalid(TitleError.BLANK)
            } else if (trimmed.graphemeCount() > MAX_LENGTH) {
                Validated.Invalid(TitleError.TOO_LONG)
            } else {
                Validated.Valid(TaskTitle(trimmed))
            }
        }
    }
}

/**
 * 両端の空白と表示されない文字を除く。表示される文字が無ければ、空文字列を返す。
 * 末尾は、最後の表示される文字の直後に続く、組になる文字（異体字セレクタとタグ文字）の連なりだけを残す。
 * 補助面の文字はサロゲートペアなので、`Char` ではなくコードポイント単位で見る。
 */
private fun String.trimEdges(): String {
    var start = 0
    while (start < length && !codePointAt(start).isVisible()) start += Character.charCount(codePointAt(start))
    if (start == length) return ""
    var visibleEnd = length
    while (!codePointBefore(visibleEnd).isVisible()) visibleEnd -= Character.charCount(codePointBefore(visibleEnd))
    var end = visibleEnd
    while (end < length && codePointAt(end).isKeptAfterVisible()) end += Character.charCount(codePointAt(end))
    return substring(start, end)
}

/** 表示される文字。空白でも、表示されない文字でもない。 */
private fun Int.isVisible(): Boolean = !isUnicodeWhiteSpace() && !isDefaultIgnorableCodePoint()

/** 見た目の 1 文字（Unicode UAX #29 の拡張書記素クラスタ）を 1 字と数えた長さ。 */
fun TaskTitle.length(): Int = value.graphemeCount()

private fun String.graphemeCount(): Int {
    val boundaries = BreakIterator.getCharacterInstance()
    boundaries.setText(this)
    var count = 0
    while (boundaries.next() != BreakIterator.DONE) count++
    return count
}

// White_Space 属性を持つ 25 文字: U+0009〜000D、U+0020、U+0085、U+00A0、U+1680、U+2000〜200A、U+2028、U+2029、U+202F、U+205F、U+3000。
// Kotlin の Char.isWhitespace（trim・isBlank が使う）は、White_Space でない U+001C〜001F を含み、White_Space の U+0085 を含まないので使わない。
// U+0009〜000D と U+0085 以外の 19 文字は、一般カテゴリ Zs・Zl・Zp と一致する
private fun Int.isUnicodeWhiteSpace(): Boolean =
    this in '\u0009'.code..'\u000D'.code || this == '\u0085'.code || Character.isSpaceChar(this)

// Default_Ignorable_Code_Point 属性を持つ 4174 コードポイント。Java・Kotlin の標準ライブラリに判定がないので、範囲を持つ。
// 出典は Unicode 15.0.0（JDK 21 が従う版）の DerivedCoreProperties.txt で、Unicode 18.0.0 でも同じ範囲である。1 行が出典の 1 行に当たる。
// 未割り当ての U+2065、U+FFF0〜FFF8、U+E0000、U+E0002〜E001F、U+E0080〜E00FF、U+E01F0〜E0FFF も、この属性を持つ。
private val defaultIgnorableRanges: List<IntRange> = listOf(
    0x00AD..0x00AD, 0x034F..0x034F, 0x061C..0x061C, 0x115F..0x1160, 0x17B4..0x17B5,
    0x180B..0x180D, 0x180E..0x180E, 0x180F..0x180F, 0x200B..0x200F, 0x202A..0x202E,
    0x2060..0x2064, 0x2065..0x2065, 0x2066..0x206F, 0x3164..0x3164, 0xFE00..0xFE0F,
    0xFEFF..0xFEFF, 0xFFA0..0xFFA0, 0xFFF0..0xFFF8, 0x1BCA0..0x1BCA3, 0x1D173..0x1D17A,
    0xE0000..0xE0000, 0xE0001..0xE0001, 0xE0002..0xE001F, 0xE0020..0xE007F, 0xE0080..0xE00FF,
    0xE0100..0xE01EF, 0xE01F0..0xE0FFF,
)

private fun Int.isDefaultIgnorableCodePoint(): Boolean = defaultIgnorableRanges.any { this in it }

// 表示される文字の直後なら、末尾でも除かない、表示されない文字の範囲。直前の文字と組になって意味を持ち、除くと見た目が変わる。
// 異体字セレクタ（Variation_Selector 属性を持つ 260 個。U+180B〜180D、U+180F、U+FE00〜FE0F、U+E0100〜E01EF）は絵文字や漢字の字形を選び、
// タグ文字（U+E0020〜E007F の 96 個）は地域の旗の絵文字を組み立てる。合計は 356 個で、どれも Default_Ignorable_Code_Point に含まれる。
// 出典は Unicode 15.0.0 の PropList.txt。
private val keptAfterVisibleRanges: List<IntRange> =
    listOf(0x180B..0x180D, 0x180F..0x180F, 0xFE00..0xFE0F, 0xE0100..0xE01EF, 0xE0020..0xE007F)

private fun Int.isKeptAfterVisible(): Boolean = keptAfterVisibleRanges.any { this in it }
```

タイトルは、前後の空白と表示されない文字を除いた後の、見た目の 1 文字（拡張書記素クラスタ）で 50 字までを受け付ける。実測で分かった点は次のとおりである。

- 空白は、Unicode の White_Space 属性を持つ文字である。この範囲は、標準ライブラリの判定と一致しない。
  - Kotlin の `isBlank` と `trim` が使う `Char.isWhitespace` は、U+001C〜001F を含み、U+0085 を含まない。
  - Java の `Character.isWhitespace` は、さらに U+00A0・U+2007・U+202F を含まない。
  - 照合は、全コードポイントを `\p{IsWhite_Space}` と比べて確かめた。
  - そのため、空白の判定は自前で書き、テストは Unicode の一覧から手で並べた文字をオラクルにする（§2.2）。
- 表示されない文字（Default_Ignorable_Code_Point）も、標準ライブラリに判定がない。正規表現に `\p{IsDefault_Ignorable_Code_Point}` はなく、`Character.isIdentifierIgnorable` は範囲が違う。
  - そのため、Unicode の `DerivedCoreProperties.txt` の範囲を定数として持つ。
  - 版は Unicode 15.0.0（JDK 21 が従う版）である。18.0.0 でも同じ範囲であることを確かめた。
  - 補助面（U+E0000〜E0FFF のタグ文字、異体字セレクタ補助など）を含むので、`codePoints()` でコードポイント単位に判定する。
  - 空白と表示されない文字だけのタイトルは拒否する。先頭からは最初の表示される文字より前を、末尾からは最後の表示される文字より後ろを除く。途中の表示されない文字は、そのまま残す。
  - 末尾に残す文字がある。直前の文字と組になる、異体字セレクタとタグ文字である。異体字セレクタは Variation_Selector 属性を持つ 260 個、タグ文字は U+E0020〜E007F の 96 個で、計 356 個である。最後の表示される文字の直後に続くものだけを残す。先頭や、空白と除く文字の後ろにあるものは除く。この範囲は、全数の検査で確かめる。
  - 補助面の文字はサロゲートペアなので、前後の除去は `Char` ではなくコードポイント単位で書く。Kotlin の `trim` は `Char` 単位なので使わない。
- 見た目の長さは `java.text.BreakIterator.getCharacterInstance()` で数える。JDK 21 で、結合文字つきの文字と国旗を 1 文字と数えることを、AC のテストで確かめている。
- 期限は、日付だけを持つ `DueDate` で表す。文字列からの変換と、`LocalDate` からの生成を、どちらも `of` に置く。どちらも下限より前の日付を拒否し、`Validated` で返す。

```kotlin
package com.example.todo.domain

import java.time.LocalDate
import java.time.format.DateTimeFormatter
import java.time.format.DateTimeParseException

enum class DueDateError { INVALID }

/** タスクの期限。日付だけを持ち、時刻は持たない。 */
@JvmInline
value class DueDate private constructor(val value: LocalDate) {
    companion object {
        /** 日付からつくる。下限（0001-01-01）より前の日付は拒否する（OI-015）。 */
        fun of(date: LocalDate): Validated<DueDate, DueDateError> =
            if (date < MIN) Validated.Invalid(DueDateError.INVALID) else Validated.Valid(DueDate(date))

        /**
         * `YYYY-MM-DD` として読めて、実在する暦日だけを受け付ける。時刻つき・別形式・実在しない日は拒否する。
         * 空文字列は形が合わないので拒否する（OI-012）。0000 年は下限より前なので拒否する（OI-015）。
         */
        fun of(raw: String): Validated<DueDate, DueDateError> {
            if (!FORMAT.matches(raw)) return Validated.Invalid(DueDateError.INVALID)
            return try {
                of(LocalDate.parse(raw, DateTimeFormatter.ISO_LOCAL_DATE))
            } catch (_: DateTimeParseException) {
                Validated.Invalid(DueDateError.INVALID)
            }
        }
    }
}

// 期限の下限。MySQL の DATE は 0 年を閏年として扱わず 0000-02-29 を保存できないので、0000 年は受け付けない（OI-015）
private val MIN = LocalDate.of(1, 1, 1)

// 4 桁の年、2 桁の月日（ASCII の数字だけ）。ISO_LOCAL_DATE は 5 桁以上の年や符号つきの年も読むので、先に形を絞る
private val FORMAT = Regex("[0-9]{4}-[0-9]{2}-[0-9]{2}")
```

`ISO_LOCAL_DATE` は、符号つきや 5 桁以上の年も読む。`YYYY-MM-DD` だけを受け付けるため、先に正規表現で形を絞る。実在しない日（`2026-02-30`）は、`ISO_LOCAL_DATE` の厳密な解決で拒否される。

アダプタ層（Spring MVC）では、DTO を境界で一度だけドメイン型へ変換し、失敗は HTTP 400 に写像する。DTO はプリミティブ（`String?`）で受け、変換の結果は `Validated` で返す。

```kotlin
package com.example.todo.adapter.web

/**
 * 登録の要求の本文。外部入力の形そのもので、ドメインの意味は持たず、アダプタ層から外へ出さない。
 * 欠落・null は Jackson に任せず null として受け、タイトルが無ければ TITLE_BLANK、期限が無ければ期限なしとして扱う。
 */
data class RegisterTaskRequest(val title: String?, val dueDate: String?)

/** 境界で一度だけドメイン型に変換した、登録の入力。 */
internal data class Registration(val title: TaskTitle, val dueDate: DueDate?)

/**
 * 登録の要求をドメイン型に変換する（Parse, don't validate）。失敗は、同時に成立している理由をすべて集めて返す（OI-011）。
 * 期限の項目が無い・null なら期限なし。空文字列は期限なしにせず、[DueDate.of] に渡して `DUE_DATE_INVALID` にする（OI-012）。
 */
internal fun RegisterTaskRequest.parse(): Validated<Registration, List<ErrorCode>> {
    val parsedTitle = TaskTitle.of(title.orEmpty())
    val parsedDue: Validated<DueDate?, *> = dueDate?.let { DueDate.of(it) } ?: Validated.Valid(null)
    if (parsedTitle is Validated.Valid && parsedDue is Validated.Valid) {
        return Validated.Valid(Registration(parsedTitle.value, parsedDue.value))
    }
    val codes = buildList {
        if (parsedTitle is Validated.Invalid) add(parsedTitle.error.toCode())
        if (parsedDue is Validated.Invalid) add(ErrorCode.DUE_DATE_INVALID)
    }
    return Validated.Invalid(codes)
}

private fun TitleError.toCode(): ErrorCode =
    when (this) {
        TitleError.BLANK -> ErrorCode.TITLE_BLANK
        TitleError.TOO_LONG -> ErrorCode.TITLE_TOO_LONG
    }
```

コントローラーは、変換の結果を `when` で受ける。拒否は 400 の ProblemDetail（RFC 9457）に、理由コードの配列 `codes` を足した本文で返す。存在しない対象は 404 と `TASK_NOT_FOUND` である（TRS の OI-001・OI-006）。成功について AC が定めるのは 2xx で、登録の 201 と操作の 200 はこの実装の選択である。API のパス、項目名、値の綴りは、TRS に出所が無い API の設計である。

```kotlin
package com.example.todo.adapter.web

@RestController
class TaskController(private val service: TaskService) {
    @PostMapping("/tasks")
    fun register(@RequestBody request: RegisterTaskRequest): ResponseEntity<*> =
        when (val parsed = request.parse()) {
            is Validated.Valid -> {
                val registered = service.register(parsed.value.title, parsed.value.dueDate)
                ResponseEntity.status(HttpStatus.CREATED).body(registered.toResponse())
            }
            is Validated.Invalid ->
                ResponseEntity.badRequest().body(problem(HttpStatus.BAD_REQUEST, parsed.error, "タイトルまたは期限が正しくありません"))
        }
    // ...（一覧・完了・未完了に戻す・完了済みの表示の選択。全体は TaskController.kt）
}

/** ProblemDetail（RFC 9457）に、理由コードの配列 `codes` を足した本文。順序は仕様にしない。 */
internal fun problem(status: HttpStatus, codes: List<ErrorCode>, detail: String): ProblemDetail =
    ProblemDetail.forStatusAndDetail(status, detail).also {
        it.setProperty(CODES_PROPERTY, codes.map(ErrorCode::name))
    }
```

コントローラーに届く前に Spring が落とす 400（本文が JSON として読めない）は、`@RestControllerAdvice` で同じ形にそろえる。

```kotlin
@RestControllerAdvice
class ApiExceptionHandler {
    @ExceptionHandler(HttpMessageNotReadableException::class)
    fun onUnreadable(): ProblemDetail =
        problem(HttpStatus.BAD_REQUEST, listOf(ErrorCode.MALFORMED_REQUEST), "リクエスト本文を読み取れません")
}
```

HTTP の確認は 2 層に分けている。層1の `TaskControllerTest` は、コントローラーを Spring なしで直接呼び、変換と 400 の写像を確かめる。層2の `TaskApiHttpTest` は、`@SpringBootTest` と実 DB（Testcontainers）で、JSON の形と、拒否のときに何も保存されないことを確かめる。

パスの識別子も、境界で一度だけドメイン型にする。形が不正な識別子（`/tasks/abc/complete` など）は、存在しないタスクと同じ 404 と `TASK_NOT_FOUND` にする（TRS の OI-012）。
`@PathVariable` を `Long` で受けると、Spring が型変換に失敗して 400 を返す。そのため `String` で受けて、自前で変換する（AC-02-09・AC-03-08）。

```kotlin
// 識別子の正規の形は、先頭にゼロを置かない ASCII の 10 進数字の並びで、Long に収まるもの。
// 符号・小数点・空白・全角数字・先頭のゼロや、Long を超える値は形が不正（同じタスクを指す別の綴りを作らない）
private val TASK_ID_FORMAT = Regex("0|[1-9][0-9]*")

/** パスの識別子を境界でドメイン型にする。形が不正なら null で、呼び出し側は存在しないタスクと同じに扱う。 */
internal fun parseTaskId(raw: String): TaskId? =
    if (TASK_ID_FORMAT.matches(raw)) raw.toLongOrNull()?.let(::TaskId) else null
```

JSON の型や形が定義と違う本文の扱いは、TRS の OI-013 で決まっている。型の自動変換はせず、型や形が違う本文は、JSON として読めない本文と同じ 400 と `MALFORMED_REQUEST` にする。定義にない項目は無視する。完了済みの表示の選択に未知の値が来たときも、400 と `MALFORMED_REQUEST` で、選択は変わらない（AC-01-29・AC-01-30・AC-06-07）。この決定は、次の 2 か所で実装している。

- `application.properties` に `spring.jackson.mapper.allow-coercion-of-scalars=false` を置く。
- 同じく `application.properties` に `fail-on-unknown-properties=false` を置き、定義にない項目を無視することを明示する。
- 文字列の項目への数値・真偽値の変換は、上の設定では止まらない。
  - `JsonMapperBuilderCustomizer`（`org.springframework.boot.jackson.autoconfigure`）の bean を置く。
  - `LogicalType.Textual` の整数・小数・真偽値からの変換を `CoercionAction.Fail` にして止める（`JacksonConfiguration`）。

実測（Spring Boot 4.1.2）は次のとおりである。`allow-coercion-of-scalars=false` だけでは、`{"title":123}` は `"123"` として登録された（201）。customizer を足すと、次のとおりになる。

| 本文 | 応答 |
|---|---|
| `{"title":123}`、`{"title":true}` | 400 と `MALFORMED_REQUEST` |
| `{"title":["a"]}`、`{"title":{"a":1}}` | 400 と `MALFORMED_REQUEST` |
| `{"title":"x","dueDate":20261130}`、期限が真偽値・オブジェクト | 400 と `MALFORMED_REQUEST` |
| `{"title":"x","unknown":1}` | 登録される。`unknown` は無視される |
| 表示の選択 `{"visibility":"UNKNOWN"}` | 400 と `MALFORMED_REQUEST`。選択は変わらない |

`MALFORMED_REQUEST` の経路は、どれも `ApiExceptionHandler` の `HttpMessageNotReadableException` である。層1の `JacksonConfigurationTest` が Spring なしで設定を、層2の `TaskApiHttpTest` が HTTP を通した結果を確かめる。

規範の規則との対応は次のとおり（規範は [02a §1.2](../../../docs/testing/02a-types-and-pbt.md#12-コンストラクタ防御)）。

- 規則1: コンストラクタは `private` とし、検証付きファクトリ（`of` / `parse`）経由でのみ生成する。
- 規則3: 不変（immutable）を基本とし、状態変更は新しい値の生成で表現する（`val` のみ、`var` を避ける）。
- 規則4: 失敗は例外ではなく `Validated`（または `Result` 相当）で返し、呼び出し側に処理を強制する。Spring の `@Valid` / Bean Validation による検証は DTO の形式チェックに留め、**ドメインの不変条件はドメイン型のファクトリを正**とする。
- 規則5: value class を DTO に直接デシリアライズしない。デシリアライザが `of` を経由せずに値を生成すると、不変条件が破られるため、DTO にドメイン型を直接使ってはならない。Jackson 3 での実測は次のとおりである。
  - 実測は `ValueClassDtoTest`（`src/integrationTest`）で、`TaskTitle` を DTO のプロパティにした検証用のコントローラーに、本文を送る。
  - Spring Boot 4.1.2 の Jackson 3 と `jackson-module-kotlin` は、`private constructor` の `TaskTitle` を生成する。
  - このとき、`TaskTitle.of` を経由しない。
  - 空のタイトル（`{"title":""}`）と 51 字のタイトルが、検証を素通りして、`TaskTitle` として存在した。
  - 文字列を包む value class でも、旧サンプルで実測した数値を包む型と同じ結果だった。そのため、DTO は `String?` で受け、`TaskTitle.of` で変換する。
  - このテストが失敗するようになった（検証が効くようになった）ら、この規則を見直す。

### 1.3 sealed 型と網羅的 `when`（網羅性チェック）

状態・種別・イベントは `sealed interface`（または `sealed class`）で表現し、分岐の網羅性をコンパイラに検査させる。Kotlin では **`when` を式として使い、`else` を書かない**。

```kotlin
package com.example.todo.domain

/** タスクの完了の状態。完了時刻などの状態ごとのデータは、要件にないので持たない。 */
sealed interface TaskStatus {
    data object Open : TaskStatus
    data object Done : TaskStatus
}
```

区分は、完了・期限・現在時刻から決まる。`when` を式として使い、`else` を置かない。`TaskStatus` に状態を足すと、この `when` がコンパイルエラーになる。

```kotlin
package com.example.todo.domain

import java.time.Clock
import java.time.LocalDate
import java.time.ZoneId

/** 一覧での区分。未完了・完了・期限切れのちょうど 1 つ。 */
sealed interface TaskCategory {
    data object Open : TaskCategory
    data object Done : TaskCategory
    data object Overdue : TaskCategory
}

/** 期限切れの判定に使うタイムゾーン。サーバーの既定のタイムゾーンや Clock のゾーンによらず、この日付で判定する。 */
val BUSINESS_ZONE: ZoneId = ZoneId.of("Asia/Tokyo")

/**
 * 区分を判定する。完了は期限によらず完了。未完了は、Asia/Tokyo の今日が期限の日付より後（期限の翌日の 0 時以降）なら期限切れ。
 * `when` に `else` を置かないので、状態を増やすとここがコンパイルエラーになる。
 */
fun Task.category(clock: Clock): TaskCategory =
    when (status) {
        TaskStatus.Done -> TaskCategory.Done
        TaskStatus.Open -> if (isPastDue(clock)) TaskCategory.Overdue else TaskCategory.Open
    }

private fun Task.isPastDue(clock: Clock): Boolean {
    val due = dueDate ?: return false
    return LocalDate.ofInstant(clock.instant(), BUSINESS_ZONE).isAfter(due.value)
}
```

区分の判定は、`Asia/Tokyo` の今日で行う。時計のゾーンも、サーバーの既定のタイムゾーンも使わない。
`LocalDate.now(clock)` は時計のゾーンを使うので、`LocalDate.ofInstant(clock.instant(), BUSINESS_ZONE)` と書く。
テストは、時計のゾーンを変えても結果が変わらないことを確かめる（§2.2）。

状態の遷移は、完了にする操作と未完了に戻す操作の 2 つで、どちらも元の状態に関わらず結果の状態を決める。再実行は何も変えない。

```kotlin
/** 完了にする。すでに完了なら変わらない。 */
fun Task.complete(): Task = copy(status = TaskStatus.Done)

/** 未完了に戻す。すでに未完了なら変わらない。 */
fun Task.reopen(): Task = copy(status = TaskStatus.Open)
```

上のコード例は、`TaskStatus.kt`・`TaskCategory.kt`・`Task.kt` から抜いたものである。`Task.kt` の package と import は省いた。

規範の規則との対応は次のとおり（規範は [02a §1.3](../../../docs/testing/02a-types-and-pbt.md#13-状態の型と網羅的な分岐網羅性チェック)）。

- 規則1: `status: String` と `Boolean` の組合せで状態を表現しない（`isOpen && isDone` のような**矛盾状態を表現可能にしない**）。
- 規則2: 規範は「状態ごとに必要なデータを各状態に持たせ」と定める。このサンプルは、完了日時を記録しない（要件定義書の Q-09）ので、状態ごとに必要なデータが無く、この規則は適用外である。`TaskStatus` の各状態はデータを持たない。要件にない値を足して、この規則を演出することはしない。
- 規則3: `when` の `else` 分岐を禁止する（sealed / enum 対象）。`else` は将来の状態追加を黙って飲み込む。
- 規則4: sealed / enum を対象にした `when` は、式でも文でも非網羅だとコンパイルエラーになる（Kotlin 1.7 以降）。加えて `allWarningsAsErrors` を有効にし、冗長な `else` 等の警告も必ずビルドエラーにする（§0）。
- 規則5: 外部から来る文字列（DB・JSON）は、境界で enum / sealed 型へ変換する。未知の値は検証失敗として拒否し、`else` で握りつぶさない（このサンプルでは読み込み時の例外）。データベースの行を `TaskStatus` へ変換する永続化のアダプタが該当する。

```kotlin
package com.example.todo.adapter.persistence

/** DB の `status` 列に保存する文字列。`TaskStatus` の型名とは独立した、永続化形式の契約。 */
internal enum class TaskStatusColumn { OPEN, DONE }

// when を「式」として使い、else を置かない。TaskStatus に状態を追加するとここがコンパイルエラーになる。
private fun TaskStatus.toColumn(): TaskStatusColumn =
    when (this) {
        TaskStatus.Open -> TaskStatusColumn.OPEN
        TaskStatus.Done -> TaskStatusColumn.DONE
    }

/**
 * 行 → タスク。未知の status と、タイトル・期限の規則に合わない行は例外で拒否する（外部の文字列を閉じた型へ。02a §1.3 規則 5）。
 * 例外の型は契約にしない。
 */
internal fun TaskRow.toTask(): Task {
    val column = TaskStatusColumn.valueOf(status) // 未知の status は IllegalArgumentException
    val validTitle = TaskTitle.of(title)
    require(validTitle is Validated.Valid) { "タイトルが規則に合わない行: id=$id" }
    return Task(
        id = TaskId(id),
        title = validTitle.value,
        dueDate = dueDate?.toDueDate(id),
        status = when (column) {
            TaskStatusColumn.OPEN -> TaskStatus.Open
            TaskStatusColumn.DONE -> TaskStatus.Done
        },
        createdAt = createdAt.toInstant(),
    )
}

private fun LocalDate.toDueDate(id: Long): DueDate =
    when (val due = DueDate.of(this)) {
        is Validated.Valid -> due.value
        is Validated.Invalid -> throw IllegalArgumentException("期限が規則に合わない行: id=$id")
    }
```

未知の `status` は、DB の `CHECK` 制約が書き込みを拒否する。`CHECK` を外して迂回して入れた行は、この変換が読み込み時に拒否する（`TaskRowTest` が層1で、`TaskRepositoryIntegrationTest` が実 DB で確かめる）。永続化の詳細は [02b §3.3](./02b.md#33-db-を含む-integration-のサンプルtestcontainers) にある。

## 2. PBT（Property-Based Testing）標準

### 2.2 Property の型（定義基準）

Kotest Property（`io.kotest:kotest-property`）での記述例。ジェネレータは `TodoGenerators.kt` に一元管理する。ファクトリの検証と同じ制約を満たす値だけを生成する。

このサンプルは、規範の分類のうち、交換則・結合則を使わない。規範は「Property は次の分類のいずれかで記述し」と定め、すべての分類の実演を求めない。交換則・結合則は、順序や括りに依存しない二項演算に使う。このサンプルには、加算などの二項演算が無い。

タイトルのジェネレータは、連結しても隣と結合しない「見た目 1 文字」の単位から作る。単独の地域指示子や先頭の結合文字は、連結すると隣と結合して数が変わるので、単位に入れない。期待する長さは、使った単位の数から決める。実装の数え方は写さない（規範は [02a §2.3](../../../docs/testing/02a-types-and-pbt.md#23-pbt-実装ルール) の規則5）。

```kotlin
/** 連結しても隣と結合しない、見た目 1 文字の単位。結合文字つき・国旗（地域指示子 2 個）・絵文字を含む。 */
val titleUnits: List<String> = listOf("a", "Z", "あ", "牛", "e\u0301", "🇯🇵", "🇺🇸", "😀")

/** 単位を [count] 個並べた文字列の生成器。見た目の長さは必ず単位の数になる。 */
fun arbUnits(count: IntRange): Arb<List<String>> = Arb.list(Arb.element(titleUnits), count)

val arbTitle: Arb<TaskTitle> = arbUnits(1..TaskTitle.MAX_LENGTH).map { title(it.joinToString("")) }
```

```kotlin
// 分類: 不変量（受理した値は不変条件を満たす。長さは単位の数になる）
"AC-01-01 任意の 1〜50 個の単位のタイトルは受理され、長さは単位の数になる" {
    checkAll(arbUnits(1..TaskTitle.MAX_LENGTH)) { units ->
        val result = TaskTitle.of(units.joinToString("")) as Validated.Valid
        result.value.length() shouldBe units.size
        result.value.value shouldBe units.joinToString("")
    }
}
```

空白と表示されない文字の判定は、Unicode の一覧から手で写した範囲を、独立のオラクルにする。White_Space は 25 文字、Default_Ignorable_Code_Point は 4174 個である。正規表現の `\p{IsWhite_Space}` は、空白の部分の補助で、同じ結果になることを確かめる。

```kotlin
/** White_Space 属性を持つ 25 文字（Unicode の定義）。 */
val whiteSpaceChars: List<Char> =
    ('\u0009'..'\u000D').toList() +
        listOf(' ', '\u0085', '\u00A0', '\u1680') +
        ('\u2000'..'\u200A').toList() +
        listOf('\u2028', '\u2029', '\u202F', '\u205F', '\u3000')

/**
 * Default_Ignorable_Code_Point 属性を持つ範囲。Unicode の DerivedCoreProperties.txt（15.0.0 と 18.0.0 で同じ）の行を、そのまま写した。
 * 実装の定数とは別に、出典から手で写した独立のオラクルである。
 */
private val defaultIgnorableLines: List<String> = listOf(
    "00AD", "034F", "061C", "115F..1160", "17B4..17B5", "180B..180D", "180E", "180F", "200B..200F", "202A..202E",
    "2060..2064", "2065", "2066..206F", "3164", "FE00..FE0F", "FEFF", "FFA0", "FFF0..FFF8", "1BCA0..1BCA3", "1D173..1D17A",
    "E0000", "E0001", "E0002..E001F", "E0020..E007F", "E0080..E00FF", "E0100..E01EF", "E01F0..E0FFF",
)

/** Default_Ignorable_Code_Point 属性を持つコードポイント（昇順）。Unicode の一覧の合計は 4174 個。 */
val defaultIgnorableCodePoints: List<Int> = defaultIgnorableLines.flatMap { line ->
    val bounds = line.split("..").map { it.toInt(16) }
    (bounds.first()..bounds.last()).toList()
}

private fun codePointString(codePoint: Int): String = String(Character.toChars(codePoint))

/** 表示されない文字の並び（1〜5 個）。補助面（U+E0000〜E0FFF など）のコードポイントを含む。 */
val arbInvisible: Arb<String> =
    Arb.list(Arb.element(defaultIgnorableCodePoints), 1..5).map { list -> list.joinToString("") { codePointString(it) } }

/**
 * 表示される文字の直後なら残す、表示されない文字。Unicode の Variation_Selector 属性を持つ 260 個（PropList.txt の
 * 180B..180D、180F、FE00..FE0F、E0100..E01EF）と、タグ文字 U+E0020〜E007F の 96 個。合計は 356 個。
 * 実装の定数とは別に、出典から手で写した独立のオラクルである。
 */
val keptAtEdgeCodePoints: List<Int> =
    (0x180B..0x180D).toList() + 0x180F + (0xFE00..0xFE0F).toList() + (0xE0100..0xE01EF).toList() + (0xE0020..0xE007F).toList()

/** 組になる文字を除いた、表示されない文字。Default_Ignorable_Code_Point から、残す文字を引いたもの。 */
val removedAtEdgeInvisibleCodePoints: List<Int> = defaultIgnorableCodePoints - keptAtEdgeCodePoints.toSet()

/**
 * 基本多言語面（U+FFFF 以下）と補助面を半々で選ぶ。一様に選ぶと、基本多言語面の文字がほとんど出ない
 * （表示されない文字 4174 個のうち 66 個）。
 */
private fun arbHalfBmp(codePoints: List<Int>): Arb<Int> =
    Arb.choice(
        Arb.element(codePoints.filter { it <= 0xFFFF }),
        Arb.element(codePoints.filter { it > 0xFFFF }),
    )

/** 残す文字の並び（1〜5 個）。基本多言語面（20 個）と補助面を半々で選ぶ。 */
val arbKeptAtEdge: Arb<String> =
    Arb.list(arbHalfBmp(keptAtEdgeCodePoints), 1..5).map { list -> list.joinToString("") { codePointString(it) } }

/**
 * 除く文字の並び（1〜6 個）。残す文字は含まない。空白、基本多言語面の表示されない文字、補助面の表示されない文字を、
 * 1 / 3 ずつ選ぶ。
 */
val arbRemovedAtEdge: Arb<String> =
    Arb.list(
        Arb.choice(
            Arb.element(whiteSpaceChars.map { it.code }),
            Arb.element(removedAtEdgeInvisibleCodePoints.filter { it <= 0xFFFF }),
            Arb.element(removedAtEdgeInvisibleCodePoints.filter { it > 0xFFFF }),
        ),
        1..6,
    ).map { list -> list.joinToString("") { codePointString(it) } }

/**
 * 先頭から除く文字の並び（1〜6 個）。先頭には組になる相手が無いので、残す文字も含む。空白、基本多言語面の表示されない文字、
 * 補助面の表示されない文字を、1 / 3 ずつ選ぶ。
 */
val arbRemovedAtStart: Arb<String> =
    Arb.list(
        Arb.choice(
            Arb.element(whiteSpaceChars.map { it.code }),
            Arb.element(defaultIgnorableCodePoints.filter { it <= 0xFFFF }),
            Arb.element(defaultIgnorableCodePoints.filter { it > 0xFFFF }),
        ),
        1..6,
    ).map { list -> list.joinToString("") { codePointString(it) } }

/** 最後の表示される文字と、残す文字の連なりの後ろから除く文字の並び。最初が除く文字で、その後ろに残す文字が続いてもよい。 */
val arbRemovedAfterKept: Arb<String> = Arb.bind(arbRemovedAtEdge, arbRemovedAtStart) { head, tail -> head + tail }

/** 表示されない文字の並び（1〜5 個）。例外の文字も含め、基本多言語面と補助面を半々で選ぶ。 */
val arbInvisibleMixed: Arb<String> =
    Arb.list(arbHalfBmp(defaultIgnorableCodePoints), 1..5).map { list -> list.joinToString("") { codePointString(it) } }

/** 空白と表示されない文字だけの並び（1〜8 個）。 */
val arbBlankOrInvisible: Arb<String> =
    Arb.list(Arb.element(whiteSpaceChars.map { it.code } + defaultIgnorableCodePoints), 1..8)
        .map { list -> list.joinToString("") { codePointString(it) } }

// 分類: 不変量（空白と表示されない文字だけのタイトルは必ず拒否される）
"AC-01-04 AC-01-05 AC-01-38 White_Space 属性を持つ文字と表示されない文字だけの、任意の並びは BLANK で拒否される" {
    checkAll(arbBlankOrInvisible, arbWhiteSpace, arbInvisible) { blank, space, invisible ->
        TaskTitle.of(blank) shouldBe Validated.Invalid(TitleError.BLANK)
        TaskTitle.of(space) shouldBe Validated.Invalid(TitleError.BLANK)
        TaskTitle.of(space + invisible) shouldBe Validated.Invalid(TitleError.BLANK)
        TaskTitle.of(invisible + space + invisible) shouldBe Validated.Invalid(TitleError.BLANK)
    }
}

// 分類: オラクル（独立のオラクルは、Unicode の一覧から手で写した whiteSpaceChars と defaultIgnorableCodePoints。正規表現の \p{IsWhite_Space} は補助）
"AC-01-05 AC-01-38 全コードポイントのうち、White_Space の 25 文字と Default_Ignorable_Code_Point の 4174 個だけが、1 文字で BLANK になる" {
    val allCodePoints = (Character.MIN_CODE_POINT..Character.MAX_CODE_POINT).toList()
    val rejected = allCodePoints.filter { TaskTitle.of(String(Character.toChars(it))) == Validated.Invalid(TitleError.BLANK) }
    defaultIgnorableCodePoints.size shouldBe 4174
    rejected shouldBe (whiteSpaceChars.map { it.code } + defaultIgnorableCodePoints).sorted()

    val property = Regex("""\p{IsWhite_Space}""")
    val whiteSpaceOnly = rejected - defaultIgnorableCodePoints.toSet()
    whiteSpaceOnly shouldBe allCodePoints.filter { property.matches(String(Character.toChars(it))) }
}
```

前後の除去は、除く文字（空白と、異体字セレクタ・タグ文字を除く表示されない文字）と、組になる文字（異体字セレクタとタグ文字）を別のジェネレータで作る。ジェネレータは、基本多言語面と補助面を同じ割合で選ぶ。組になる文字の範囲は、実装の定数とは別に、出典から手で写して、全数の検査でも使う。先頭用のジェネレータは、先頭には組になる相手が無いので、組になる文字も含む。

```kotlin
fun saved(raw: String): String? = (TaskTitle.of(raw) as? Validated.Valid)?.value?.value

"AC-01-39 前後の空白と表示されない文字の並びは、除かれる" {
    checkAll(arbUnits(1..22), arbRemovedAtStart, arbRemovedAtEdge) { units, before, after ->
        val core = units.joinToString("")
        saved(before + core + after) shouldBe core
        saved(before + core) shouldBe core
        saved(core + after) shouldBe core
    }
}

// 分類: 不変量（組になる文字は、表示される文字の直後に続くときだけ残る。その後ろは除かれる。先頭や、除く文字の後ろのものは除かれる）
"AC-01-40 表示される文字の直後の異体字セレクタとタグ文字は残り、それ以外の位置のものは除かれる" {
    checkAll(arbUnits(1..22), arbKeptAtEdge, arbRemovedAtStart, arbRemovedAfterKept) { units, kept, before, after ->
        val core = units.joinToString("")

        saved(before + core + kept + after) shouldBe core + kept

        saved(core + after) shouldBe core
    }
}

// 分類: 不変量（字数は両端を除いた後で数える。除く前は 51 字以上でも、除いた後が 50 字なら受理される）

// 分類: オラクル（全ての表示されない文字について、表示される文字の直後・先頭・空白の後ろで、残るか除かれるかを、手で写した範囲と照合する）
"AC-01-39 AC-01-40 Default_Ignorable_Code_Point の 4174 個は、表示される文字の直後では 356 個だけが残り、先頭と空白の後ろでは全部除かれる" {
    keptAtEdgeCodePoints.size shouldBe 356
    val kept = keptAtEdgeCodePoints.toSet()
    defaultIgnorableCodePoints.forEach { codePoint ->
        val invisible = String(Character.toChars(codePoint))

        saved("${invisible}牛") shouldBe "牛"
        saved("牛 $invisible") shouldBe "牛"
        saved("牛\u200B$invisible") shouldBe "牛"
        saved("牛$invisible\u200B") shouldBe if (codePoint in kept) "牛$invisible" else "牛"
    }
}
```

区分の判定は、TRS の制約表（日付と状態の表）をオラクルにする。時刻は、Asia/Tokyo の規則が一定の期間（1952〜2100 年）に限って生成する。1951 年以前は夏時間や地方平均時があり、+09:00 を固定で使うオラクルが成り立たない。

```kotlin
/** Asia/Tokyo の規則が一定の期間（1952〜2100 年）の期限。+09:00 のオラクルで検証できる。 */
val arbModernDueDate: Arb<DueDate> =
    Arb.long(LocalDate.of(1952, 1, 1).toEpochDay()..LocalDate.of(2100, 12, 31).toEpochDay()).map { due(LocalDate.ofEpochDay(it)) }

// 分類: 境界
// 期限の日の 0 時 0 分（JST）から、期限の翌日の 0 時 0 分（JST）までを、境界の前後 1 ミリ秒で確かめる
test("AC-04-01 期限の翌日の 0 時 0 分（JST）の 1 ミリ秒前は未完了、ちょうどで期限切れになる") {
    checkAll(arbModernDueDate) { dueDate ->
        val start = dueDate.value.atStartOfDay(tokyo).toInstant()
        val nextDay = dueDate.value.plusDays(1).atStartOfDay(tokyo).toInstant()
        val open = Task(TaskId(1), title("a"), dueDate, TaskStatus.Open, Instant.EPOCH)
        open.category(Clock.fixed(start, ZoneOffset.UTC)) shouldBe TaskCategory.Open
        open.category(Clock.fixed(nextDay.minusMillis(1), ZoneOffset.UTC)) shouldBe TaskCategory.Open
        open.category(Clock.fixed(nextDay, ZoneOffset.UTC)) shouldBe TaskCategory.Overdue
    }
}

// 分類: オラクル（完了・期限・現在時刻から区分を決める別の書き方と照合する）
test("AC-04-02 AC-04-01 どのタスクも、区分は未完了・完了・期限切れのちょうど 1 つで、完了と期限と現在時刻のオラクルに一致する") {
    val arbNow = Arb.long(
        OffsetDateTime.parse("1990-01-01T00:00+09:00").toInstant().toEpochMilli()..OffsetDateTime.parse("2100-12-31T00:00+09:00").toInstant().toEpochMilli(),
    )
    checkAll(arbTaskId, arbModernDueDate, arbStatus, arbNow) { id, dueDate, status, nowMillis ->
        val now = Instant.ofEpochMilli(nowMillis)
        val withDue = Task(id, title("a"), dueDate, status, Instant.EPOCH)
        val withoutDue = withDue.copy(dueDate = null)
        val pastDue = !now.isBefore(dueDate.value.plusDays(1).atStartOfDay(tokyo).toInstant())
        val expected = when (status) {
            TaskStatus.Done -> TaskCategory.Done
            TaskStatus.Open -> if (pastDue) TaskCategory.Overdue else TaskCategory.Open
        }
        withDue.category(Clock.fixed(now, ZoneOffset.UTC)) shouldBe expected
        // 期限がなければ、完了か未完了のどちらかで、期限切れにはならない

            if (status == TaskStatus.Done) TaskCategory.Done else TaskCategory.Open
    }
}

// 分類: 単調性。現在時刻が進むと、未完了のタスクは「期限内 → 期限切れ」にだけ変わり、戻らない

}
```

#### 操作列の PBT（状態遷移）

```kotlin
// 分類: オラクル（操作列。04 §2.2 の状態遷移の抜けの還元先）。オラクルは制約表の 2 × 2（C-20〜C-23）:
// 完了にする操作は結果を完了に、未完了に戻す操作は結果を未完了にし、どちらも元の状態に関わらない。
"AC-02-01 AC-02-08 AC-03-01 AC-03-06 任意の操作列の後、各タスクの状態は最後の操作で決まり、状態以外とほかのタスクは変わらない" {
    checkAll(arbTasks, Arb.list(arbOperation, 0..30)) { initial, operations ->
        val current = initial.toMutableList()
        val lastOperation = mutableMapOf<TaskId, Operation>()
        operations.forEach { operation ->
            if (current.isNotEmpty()) {
                val index = operation.target % current.size
                val target = current[index]
                current[index] = operation.kind.applyTo(target)
                lastOperation[target.id] = operation
            }
        }
        current.map { it.id } shouldBe initial.map { it.id }
        current.zip(initial).forEach { (after, before) ->
            after.copy(status = before.status) shouldBe before
            val expected = lastOperation[before.id]?.kind?.resultingStatus ?: before.status
            after.status shouldBe expected
        }
    }
}
```

操作の種類（完了にする・未完了に戻す）と対象の位置は、`Arb.bind` で独立に生成し、`Arb.list(arbOperation, 0..30)` で操作列にする。
対象の一覧は `arbTasks` で、識別子が重ならず、期限と登録時刻が重なりやすいタスクの一覧である。
オラクルは制約表の 2 × 2（C-20〜C-23）で、実装の `when` とは別に、操作の種類から結果の状態を決める。
このテストは、時刻を生成しない。全体は `src/test/kotlin/com/example/todo/domain/TaskTest.kt` にある。

### 2.3 PBT 実装ルール

規範の規則との対応は次のとおり（規範は [02a §2.3](../../../docs/testing/02a-types-and-pbt.md#23-pbt-実装ルール)）。

- 規則1: 各型に `arbXxx`（Kotest の `Arb`）を1つ用意し、ファクトリの検証と同じ制約を満たす値を生成する。
- 規則2: 「範囲外の入力は必ず `Validated.Invalid` を返す」を Property にする。
- 規則3: Kotest 6.2.5 は、失敗した Property のメッセージに `Repeat this test by using seed <値>` を**既定で出力する**（設定は不要）。そのシードを `PropTestConfig(seed = <値>)` に渡すと同じ失敗を再現できる（`PropTestConfig` は `@ExperimentalKotest` の opt-in が必要）。この挙動と出力の形式は `PropertyTestingConfigTest` が、わざと落ちる Property で検証している（Kotest の更新で変わったら落ちる）。
- 規則4: 実行回数の既定は 1000 回（`kotest.proptest.default.iteration.count`）。Gradle の `-D` はテスト JVM に渡らないため、`build.gradle.kts` が `-Pproptest.iterations=N` をこのシステムプロパティに転送している。夜間ジョブ（`.github/workflows/nightly-mutation.yml` の `pbt`）は `./gradlew test -Pproptest.iterations=10000` で実行する（全体テストが約 20 秒で完了することを実測した）。

#### 2.3.1 PBT が失敗したときの AI の手順

規範の [02a §2.3.1](../../../docs/testing/02a-types-and-pbt.md#231-pbt-が失敗したときの-ai-の手順) の各手順を、Kotest 6.2.5 で実施するときの具体を示す。シードを指定した再現は `PropTestConfig(seed = <値>)` で行う。

1. ログからシードと縮小後の反例を取り出す。Kotest 6.2.5 の失敗メッセージを、`Arb.int(0..1000)` に対し `check(it < 500)` で落ちる Property で実測した出力が下の例である。縮小後の反例は `Arg <引数番号>: <縮小後の値> (shrunk from <縮小前の値>)` の行に、シードは `Repeat this test by using seed <値>` の行にある。エッジケース（範囲の端や特別な値。`Arb.int(0..1000)` なら 0・1・1000 など）は、既定で約 2% の確率で混ざる。エッジケースで落ちると縮小されず、`(shrunk from …)` が付かない `Arg 0: 1000` の形式で出力される。どちらの形式でも、`Arg` の行の値がそのまま反例である。

      ```text
      Property failed after 1 attempts

          Arg 0: 500 (shrunk from 988)

      Repeat this test by using seed -2729266846478331732

      Caused by IllegalStateException: boom
      ```

2. `PropTestConfig(seed = <値>)` で同じ失敗が再現することを確認する（一時的。コミットしない）。
   - 保存済みシードの扱いの Kotest での具体は、下の [§2.3.2](#232-保存済みシードの扱い) のとおり。

#### 2.3.2 保存済みシードの扱い

規範の [02a §2.3.2](../../../docs/testing/02a-types-and-pbt.md#232-保存済みシードの扱い) の規則を、Kotest 6.2.5 で実施するときの具体を示す。規則は規範に従う。

- 保存機能: 保存は `PropertyTesting.writeFailedSeed` が制御し、既定で有効である。Kotest 6.2.5 で確認した挙動では、Property が失敗するとシードをローカルに保存する。
- 保存先: `$XDG_CACHE_HOME/.kotest/seeds` である。環境変数 `XDG_CACHE_HOME` が未設定か空白なら、`~/.kotest/seeds` になる。
- 再利用の条件: 保存したシードは、次の 2 つを満たす実行で再利用される。
  - (a) `PropTestConfig(seed = …)` を指定しない。
  - (b) テストパスが同じである。
- 消えるとき: 保存シードはそのテストが成功すると消える。わざと落とすテストでは成功しないため消えず、固定され続ける。
